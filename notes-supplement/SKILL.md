# 课程笔记补充工具 (notes-supplement)

## 概述

本 skill 用于将语音文字稿（STT）中的讲解内容补充到已有的课程笔记中。它**保持原笔记内容一字不改**，将语音内容无缝整合到原文相应位置，生成出版级质量的完整笔记。

> **前置步骤**：如果笔记中包含需要识别文字的PPT图片，请先运行 `image-ocr` skill 处理图片，再将输出的 `_ocr.md` 文件作为本 skill 的输入。

**核心原则（v2.0 重构）**：
- ✅ **图片OCR独立化**：图片识别由 `image-ocr` skill 单独处理，本 skill 专注于语音内容整合
- ✅ **内容优先级**：**原始笔记 > 语音识别文字稿**
  - 1️⃣ 笔记作者手写内容最权威
  - 2️⃣ 语音STT可能有口误和遗漏
- ✅ **智能去重**：整合时检测重复内容，笔记已有的内容不再用STT重复添加
- ✅ **原笔记内容一字不改**，只补充、不修改
- ✅ **无缝整合**：语音内容融入原文相应位置，不使用块标注
- ✅ **绝不添加外部资料**：不加任何PPT以外的外部知识
- ✅ 保存为新文件，源文件保持不变

**v2.0 废弃的原则**：
- ❌ 不再内置图片OCR功能（移交 `image-ocr` skill）
- ❌ 不再使用PaddleOCR（改用大模型视觉识别）

**保留的旧原则**：
- ❌ 不再使用 `> [!NOTE] AI补充` 块标注
- ❌ 不添加任何PPT以外的外部资料

**保留的核心原则**：
- ✅ **绝不简化内容**：原笔记和STT中的所有细节、例子、列表项必须全部保留，不得合并、缩写或"优化"掉任何内容
- ✅ **图片和引用块绝对保留**：原笔记中的所有 `![](url)` 图片链接及其 `> 引用注释` 必须 100% 保留，不得删除或替换（详见下方的「绝对禁令」章节）
- ✅ **逐句匹配，逐句补充**：找到STT内容在原文中的精确位置，直接在对应位置插入，不得大段合并到末尾

## 与 image-ocr 的协作

```
image-ocr skill              →       notes-supplement（本skill）
用大模型视觉识别图片                整合STT语音、PPT补全、格式化排版
提取文字、更新图片说明
输出: xxx_ocr.md                   输入: xxx_ocr.md（或原始笔记）
                                    输出: xxx_出版级.md
```

**推荐工作流**：
1. 先运行 `image-ocr` 处理笔记中的图片，输出 `笔记_ocr.md`
2. 再将 `笔记_ocr.md` 作为本 skill 的输入，整合STT语音内容

如果笔记中没有图片，或图片文字已经由 image-ocr 处理完毕，则直接使用本 skill。

## 何时使用

- 你已有课程笔记（Markdown 格式，图片已处理或无需处理），想把语音/视频文稿中的遗漏讲解补充进去
- 原笔记格式为子弹列表，想转换为规范的出版级 Markdown 格式
- 需要逐段匹配文稿与笔记章节

## ⚠️ 绝对禁令（违反将导致内容丢失）

以下禁令必须严格执行，违反将导致用户笔记内容丢失：

1. **禁止删除图片**：原笔记中的所有 `![](url)` 图片链接必须 **100% 保留**，不得以任何形式删除、替换为文字描述或省略。图片是笔记的有机组成部分，不是可选的装饰。
2. **禁止删除引用块**：图片下方的 `> 引用注释`（即 image-ocr 提取的文字）必须 **100% 保留**，不得删除、合并或重写为普通段落。
3. **禁止"翻译"图片内容**：图片就是图片，`![](url)` 就是图片链接。不得将图片链接"转换"为文字描述，也不得删除图片链接后仅保留 OCR 文字。
4. **输出前强制检查清单**（不可跳过）：
   - [ ] 新文件中的 `![](` 数量是否与原 OCR 文件一致？
   - [ ] 新文件中的 `> ` 引用块数量是否与原 OCR 文件一致？
   - [ ] 所有图片链接前后是否各有空行？
   - 如果以上任意一项为"否"，**禁止输出**，必须修正。

## 工作流程（v2.0 重构）

### 🟡 第一步：读取输入源

读取两个输入源：

1. **笔记文件**（图片已由 `image-ocr` 处理，或原始无图片笔记）
2. **STT 语音文稿**：一个或多个 `.md` 文件

```
Read <笔记文件路径>
Read <STT文件1> <STT文件2> ...
```

#### 建立内容去重检测

在整合前，对两源内容进行片段化和相似度检测：

```python
# 对每一段STT内容，检测是否已存在于原始笔记中
def is_content_duplicate(stt_text: str, original_notes: str) -> bool:
    """检测STT内容是否已存在于原始笔记中"""
    # 提取核心关键词（去掉停用词："那么"、"然后"等）
    # 计算文本相似度（如Jaccard相似度 > 0.7 视为重复）
    # 笔记中已有的内容，STT不再重复添加
    return False
```

**去重规则**：

| 内容重合情况 | 处理方式 | 保留来源 |
|-------------|---------|---------|
| 笔记已有 ✅ + STT有 ✅ | STT重复，不添加 | 笔记原文 |
| 笔记无 ❌ + STT有 ✅ | 全新内容，需要补充 | STT |
| 笔记有部分 ✅ + STT有更多细节 ✅ | 只补充笔记中没有的部分 | 笔记为主，STT补充细节 |

### 🟡 第二步：PPT内容补全（针对老师没念的列表）

老师讲课的普遍规律：
- ✅ 会讲**概念定义**、**意义**、**例子**
- ❌ **不会念完长列表**，会用"等等"、"比如"、"之类的"跳过

**正确处理方式（优先级从高到低）**：

1. **从已处理的图片OCR内容中提取**：如果笔记已由 image-ocr 处理，图片下方的引用块是最准确的来源
2. **从语音文字稿中提取**：搜索关键词，看老师念了几个
3. **PPT是通用知名内容**：如《人物志》十二材、大五人格等，直接用标准列表名称
4. **无法确定**：标注 `[PPT列表待补充：XX种]`，不要自己瞎编

**绝对禁止**：
- ❌ 不要添加PPT以外的内容
- ❌ 不要自己杜撰列表项名称
- ❌ 不要用外部知识补充

### 🟡 第三步：匹配 STT 内容到笔记章节

根据两种方式建立映射：

**方式一：章节编号对应**
- 笔记的 `## L007` 对应 `STT/L007.md` 或 `STT/L001.md`（早期引论课）

**方式二：内容主题匹配**
- 将 STT 文稿拆分为主题段落
- 每个主题匹配到笔记中最相关的章节
- 同一段 STT 内容可补充到多个相关章节

### 🟡 第四步：无缝整合语音内容

**不要用块标注！不要用块标注！不要用块标注！**

将语音内容直接放到原文相应位置：

1. **原笔记已有一句话概括**（如"体别=十二种典型人格"）：
   - 在冒号或句号后，直接补充列表内容
   - 例：`体别 = 十二种典型人格：强毅之人、柔顺之人、雄悍之人...`

2. **原笔记是段落文字**：
   - 语音中的补充例子、解释直接接在段落末尾

3. **原笔记是列表项**：
   - 补充的列表项直接追加在后面

4. **需要说明来源的特殊情况**：
   - 只有在"老师明显口误修正"这种特殊情况才加括号标注
   - 例：`（老师口误：实际应为XXX）`

**内容处理规则**：

> ⚠️ **重要警告：绝不简化内容！** 原笔记和STT中的所有细节、例子、列表项、解释、比喻、案例必须100%全部保留。不得合并、缩写、"总结"、"提炼"或"优化"掉任何内容。用户要的是**完整的讲课实录**，不是你的"读书笔记"。

1. **口误修正**：根据上下文纠正错误数字/人名，用括号轻标
2. **口头禅过滤**：自动过滤"那么"、"然后"、"就是说"、"呃"、"啊"
3. **方言处理**：根据语境推断原意
4. **语义整理**：将零碎的即兴讲话整理为通顺的段落
5. **冗余删除**：去除重复表达的同一观点（但保留不同角度的阐述）
6. **教师语气保留**：保留原讲解中的关键语气和强调内容
7. **逐句匹配原则**：找到STT每一句话在原文中的精确对应位置，直接在该处插入，不得大段合并到章节末尾
8. **宁滥勿缺原则**：如果不确定STT内容对应哪个位置，就在最相关的位置插入，不要跳过不处理

### 🟡 第五步：格式重排

将原始子弹列表转换为规范的 Markdown 格式：

```
原始格式（Logseq/子弹笔记）：
- ## L007: 人性单元
  - Key arguments
    - 要点1
  - ### 子标题
    - 内容段落

新格式（出版级）：
## L007: 人性单元

### Key arguments

- 要点1

### 子标题

内容段落。
```

**转换规则**：
- `- ## L0XX` → `## L0XX`（二级标题，前后空行）
- `- ### 内容` → `### 内容`（三级标题，前后空行）
- `- 纯文字段落（超过30字）` → 转为普通段落
- `- 列表项（短句）` → 保留为无序列表
- `- [[wikilinks]]` → 保留原样（Obsidian 链接）
- `- #tags` → 保留原样
- **嵌套子弹列表** → 转为有序或无序子列表
- **保留所有图片链接不变**，图片前后各空一行，不得删除或替换为文字
- **保留所有引用块不变**，不得删除或合并为普通段落

### 🟡 第六步：保存输出

输出文件命名规则：
- 整合完成版：`{原文件名}_出版级.md`
- 中间版本不要用"出版级"字样，避免混淆

```
Write <笔记目录>/<原文件名_出版级.md>
```

**务必确认源文件未被修改**。

## 常见问题处理

### 语音文字稿的问题

| 问题类型 | 示例 | 处理方式 |
|---------|------|---------|
| 口误 | 讲错数字/人名 | 用括号轻标修正：`（应为：XXX）` |
| 口头禅 | "那么"、"然后"、"呃"、"啊" | 自动过滤，不影响阅读 |
| 方言识别错误 | 方言词汇被转错 | 根据语境推断原意 |
| 语义不连贯 | 即兴讲课跳跃、重复 | 理清逻辑顺序，提炼核心观点 |
| 句子碎片 | 断句错、语法不完整 | 整理为通顺段落 |
| 老师说"等等"、"比如" | 列表只念了前3个 | 从笔记中已有的图片OCR内容补充完整列表 |

### 补充粒度

推荐策略：**逐句匹配**。找到原文对应位置直接插入，而非全文读完后统一在末尾补充。

### 补充内容类型优先序

1. 老师讲解的例子 > 概念解释 > 课堂闲聊
2. 只补充原笔记没有的，原笔记有的不要重复
3. 绝不添加PPT以外的外部资料

## 使用示例

```
用户输入：
- 笔记文件：/path/to/CH1人性单元_ocr.md（已由 image-ocr 处理过图片）
- STT 目录：/path/to/STT/（含 L001-L006.md）
- 要求：整合语音内容

预期操作：
1. Read CH1人性单元_ocr.md → 了解结构（图片文字已在引用块中）
2. Read STT/L001.md ... L006.md → 获取所有文稿
3. 智能去重检测：将STT内容与笔记对比，过滤重复部分
4. 整合语音独有内容到对应章节
5. 重排格式为规范Markdown
6. 写入 CH1人性单元_出版级.md
```

## 注意事项

- 确保原始笔记文件的 frontmatter（YAML 头部）被完整保留
- **宁可不补，不要补错**：不确定的内容宁愿留空也不要脑补
- 原笔记的错别字不要修正，保持原样
- 同一处内容同时出现在多个STT文件中，取最完整的那一个
- 处理前创建任务列表跟踪进度
- **图片OCR请先用 image-ocr skill 处理**，本 skill 专注于语音内容整合 and 格式重排
